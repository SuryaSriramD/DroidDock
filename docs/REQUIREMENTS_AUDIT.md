## Scope and evidence rules

PRD §8 defines the MVP: select an existing AVD, boot it headlessly, interact smoothly inside the native window, use core controls, install an APK and capture a screenshot without Android Studio/Terminal during normal use. P0 requirements and PRD §10 release gates apply to this release. Separate native device windows are explicitly the MVP multi-device direction in PRD §4, so basic isolated simultaneous sessions cannot be discarded simply because richer resource behavior is P1.

P1 developer-workflow features remain intended product scope, with their original roadmap priority visible below. The full AVD wizard, system-image marketplace, advanced multitouch, advanced simulation, deep debugging and cloud devices are explicitly deferred by PRD §8. A local MVP build does not imply completion of the entire roadmap or notarized production distribution.

**Implemented** means current source provides the behavior; **unit verified** means the relevant automated tests passed; **live verified** always names the actual scope. **Pending** means the matching evidence or behavior is still missing. Tests and probe commands do not substitute for native UI acceptance, physical presentation measurements, or compatibility across untested hosts.
